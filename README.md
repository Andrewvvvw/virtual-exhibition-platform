# Лабораторная работа 2

Каркас платформы виртуальных выставок и ярмарок.

Сохранены классы базовой модели, их атрибуты, связи и сигнатуры методов.

Реализованы запуск приложения, отображение форм и переходы между ними.
Для посетителя добавлен демонстрационный просмотр стенда и одного экспоната с готовым описанием и ценой.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m src.main
```

## Экраны и переходы

Для демонстрации ничего вводить не требуется: **«Войти / Регистрация» →
«Найти выставку» → «Подключиться / Создать выставку»**. Имя, пароль, роль
посетителя, выставка и код билета заполнены заранее. Откроется стенд `A-104`
с карточкой «Контроллер ПЛК-500», характеристиками и ценой `2 450 BYN`.
«Запросить консультацию» показывает уведомление; его кнопка OK возвращает
к экспонату. С выставки также можно вернуться к выбору выставки или в меню.

1. **Вход / регистрация.** Кнопка «Войти / Регистрация» открывает главное
   меню при любых значениях полей. Выбранная роль и имя отображаются в меню.
   «Выход» закрывает приложение.
2. **Главное меню.** «Найти выставку» открывает форму выставки,
   «Создать стенд» — форму стенда, «Выйти из аккаунта» — форму входа.
   Переходы доступны для каждой роли.
3. **Выставка.** Поля названия, даты, времени и кода билета соответствуют
   макету. Для посетителя «Подключиться / Создать выставку» открывает
   просмотр экспоната, для остальных ролей — уведомление.
   «Назад» возвращает в главное меню.
4. **Создание стенда.** Поля номера, компании, экспоната и цены соответствуют
   макету. «Сохранить / Создать стенд» открывает уведомление,
   «Назад» возвращает в главное меню.
5. **Уведомление.** «OK» возвращает в главное меню, «Выход из программы»
   завершает приложение. После запроса консультации OK возвращает
   на выставку. Метод `showErrorMessage` показывает ошибку
   на этом же экране и позволяет вернуться к исходной форме.
6. **Просмотр выставки.** Дополнительный демонстрационный экран показывает
   компанию, стенд и экспонат средствами `Catalog2DRenderer`.

Тексты об успешной операции демонстрируют макет; данные не создаются
и не сохраняются. Экраны реализованы страницами `QStackedWidget` в одном
настольном окне. Закрытие окна и `Ctrl+C` также завершают приложение.

## Классы базовой модели

| Класс | Модуль |
| --- | --- |
| `AppInjector` | `src/core/app_injector.py` |
| `StandUI` | `src/ui/stand_ui.py` |
| `IStandRenderer` | `src/ui/stand_renderer.py` |
| `Catalog2DRenderer` | `src/ui/catalog_2d_renderer.py` |
| `MeetingController` | `src/controllers/meeting_controller.py` |
| `TicketService` | `src/services/ticket_service.py` |
| `MeetingService` | `src/services/meeting_service.py` |
| `DatabaseRepository` | `src/repositories/database_repository.py` |
| `Exhibition` | `src/models/exhibition.py` |
| `Stand` | `src/models/stand.py` |
| `Exhibit` | `src/models/exhibit.py` |
| `Ticket` | `src/models/ticket.py` |
| `MeetingRequest` | `src/models/meeting_request.py` |

`AppInjector` создаёт репозиторий-заглушку, сервисы, контроллер, рендерер
и интерфейс. Зависимости передаются конструкторам. `IStandRenderer` —
абстрактный интерфейс с операцией `renderStandView`, которую переопределяет
`Catalog2DRenderer`. Композиции `Exhibition → Stand` и `Stand → Exhibit`
представлены коллекциями в соответствующих классах.

Вспомогательные методы `StandUI` только строят формы и переключают экраны.
`renderStartPage` открывает вход, `renderStandPage` — форму выставки.
Три направления развития (3D, вебинары и B2B-заказы) в базовую версию
не включены.

## Проверка

```bash
QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -v
```

Проверяются запуск, переходы для каждой роли, действия с пустыми полями,
просмотр экспоната без ввода данных, возвраты из уведомлений и завершение приложения.
Для обычного запуска `QT_QPA_PLATFORM=offscreen` задавать не нужно.
